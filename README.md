# vpn-to-proxy

Панель, которая превращает VPN-подписку в набор обычных прокси: на каждый
коннект из подписки выдаётся SOCKS5, HTTP и HTTPS прокси со своим портом,
логином и паролем.

```
подписка (base64 / ссылки / JSON / YAML)
        │
        ├─ разбор → нормализованные коннекты (VLESS, Trojan, Shadowsocks, VMess, Hysteria2, TUIC)
        │
        ├─ на каждый коннект: порт + случайные логин и пароль
        │
        └─ конфиг sing-box: inbound (socks/http/https) → route → outbound ноды
                    │
                    └─ клиент → 1.2.3.4:20001 → VPN-нода → интернет
```

## Возможности

- **Входные форматы.** Ссылка на подписку или вставленный текст. Автоопределение:
  base64, список ссылок (`vless://`, `trojan://`, `ss://`, `vmess://`, `hysteria2://`,
  `tuic://`), JSON sing-box, JSON Xray, YAML Clash/Meta.
- **Поддержка транспортов.** REALITY, XTLS-Vision, uTLS-отпечатки, WebSocket,
  gRPC, HTTPUpgrade, HTTP/2, обфускация Shadowsocks (SIP003).
- **Прокси трёх видов** на каждый коннект: SOCKS5, HTTP CONNECT и HTTPS
  (CONNECT поверх TLS) — каждый на своём порту, с отдельными учётными данными.
- **Учётные данные** генерируются случайно и редактируются: логин, пароль и порт
  можно поменять вручную или перевыпустить пачкой.
- **Умное обновление подписки.** Коннекты сопоставляются по отпечатку, а не по
  имени или позиции: при обновлении порты и пароли остаются за теми же нодами.
  Пропавшие ноды помечаются, но не удаляются молча.
- **Проверка работоспособности.** Периодически и по кнопке: реальный запрос через
  каждый прокси с замером задержки и определением внешнего IP.
- **Экспорт**: строки подключения, `host:port:логин:пароль`, JSON, CSV.
- **Интерфейс** со светлой и тёмной темой, поиском, фильтрами, массовыми
  операциями и пагинацией.

## Требования

- Docker и Docker Compose
- Домен, если нужны HTTPS-прокси с доверенным сертификатом
- Открытый диапазон портов для прокси (по умолчанию 20000–29999)

## Быстрый старт

```bash
git clone <репозиторий> vpn-to-proxy && cd vpn-to-proxy
cp .env.example .env
```

Отредактируй `.env` — минимум `APP_SECRET` и `PUBLIC_HOST`:

```bash
openssl rand -base64 48   # значение для APP_SECRET
```

Запуск:

```bash
docker compose up -d --build
```

Панель поднимется на `http://127.0.0.1:8080` (порт задаётся в `PORT`).
Логин — `admin`, пароль берётся из `ADMIN_PASSWORD`; если он пуст, пароль
генерируется и один раз печатается в лог:

```bash
docker compose logs app | grep -A 4 'Создан администратор'
```

## Разработка

```bash
npm install
docker compose up -d mongo      # или свой mongod на 27017
npm run dev                     # API :8080 + Vite :5173
```

Полезное:

```bash
npm run build       # сборка фронтенда в server/public и компиляция сервера
npm test            # тесты парсеров подписок
npm run typecheck

# Разбор подписки без запуска панели — показывает формат, протоколы и причины пропусков
npx tsx server/scripts/probe-subscription.ts '<url>' -H 'x-hwid: ...'
```

## Заметки по эксплуатации

### Подписки с привязкой к устройству

Панели вроде Remnawave отдают полный список нод только при наличии заголовка
`x-hwid`; без него приходит одна нода-заглушка. Значения по умолчанию
(`User-Agent` и `x-hwid`) задаются в настройках, а каждая подписка может
переопределить их своими заголовками.

### Публикация портов

В `docker-compose.yml` контейнер приложения работает в режиме `network_mode: host`.
Это не оптимизация, а необходимость: публикация тысяч портов через обычный bridge
поднимает по `docker-proxy` на каждый порт и исчерпывает память.

### Сертификат для HTTPS-прокси

Три режима в настройках:

- **Самоподписанный** — панель выпускает свой CA; его можно скачать и добавить
  в доверенные.
- **Файлы на диске** — путь к `fullchain.pem` и `privkey.pem`, например от
  certbot. Каталог `/etc/letsencrypt` монтируется в контейнер только на чтение.
  После продления сертификата ядро нужно перезапустить — для этого ставится
  deploy-hook certbot.
- **Вставить PEM** — сертификат и ключ вводятся вручную.

### Чего sing-box не умеет

Транспорт `xhttp` существует только в Xray, поэтому такие ноды пропускаются
с явным предупреждением в отчёте об обновлении. То же касается `mKCP`,
ShadowsocksR и Snell.

## Как это устроено

```
server/
  src/
    core/
      parsers/     разбор подписок → outbound sing-box + отпечаток ноды
      singbox/     генерация конфига и супервизор процесса
      tls.ts       сертификаты для HTTPS-прокси
      ports.ts     выделение портов из диапазона
    services/      подписки, ноды, прокси, проверка, настройки, синхронизация
    http/          Fastify: маршруты, авторизация, обработка ошибок
web/
  src/
    components/    дизайн-система на Radix UI, темы, пагинация
    pages/         обзор, подписки, прокси, журнал, настройки
```

Ключевые решения:

- **sing-box как ядро.** Один бинарь, JSON-конфиг, маршрутизация по тегу inbound
  и `http`-inbound с TLS «из коробки» — HTTPS-прокси не требует надстроек.
- **Отпечаток ноды** вместо имени: провайдеры переставляют и переименовывают
  ноды, а выданные пользователю адреса меняться не должны.
- **Проверка конфига до применения.** Новый конфиг сначала проходит
  `sing-box check` во временном файле и только потом заменяет рабочий —
  битая подписка не может уронить уже работающие прокси.
- **Порт как ресурс с уникальным индексом.** Захват порта атомарен за счёт
  уникального индекса MongoDB, транзакции не нужны.
- **Секреты шифруются** (AES-256-GCM ключом из `APP_SECRET`): пароли прокси,
  содержимое подписок, параметры нод. Пароли пользователей — scrypt.

## Переменные окружения

Полный список с комментариями — в [.env.example](.env.example). Всё, что
меняется в рантайме (публичный хост, диапазон портов, виды прокси, TLS,
интервалы), после первого запуска редактируется в панели: источником истины
становится база.
